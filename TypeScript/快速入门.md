# 二、基本类型
## 1.自动类型判断  
当对变量的声明和赋值是同时进行的，TS 编译器会自动判断变量的类型，所以如果你的变量的声明和赋值时同时进行的，可以省略掉类型声明。  
```js
  let count = 2;
  count = "two";
  console.log(count); // 2
```
这里编译后输出`Type 'string' is not assignable to type 'number'.`效果等同于`let count: number = 2;`  

## 2.`any` 与 `unknown` 的区别

`any` 和 `unknown` 都可以表示任意类型的值，但**最大的区别在于：`any` 允许直接进行各种操作，而 `unknown` 必须先进行类型检查，才能安全地使用。**

### 一、基本区别

| 对比 | `any` | `unknown` |
|---|---|---|
| 含义 | 任意类型，关闭类型检查 | 未知类型，需要先确认类型 |
| 赋值给其他类型 | 可以 | 通常不可以，需要类型检查或断言 |
| 访问属性 | 可以直接访问 | 不可以直接访问 |
| 调用方法 | 可以直接调用 | 不可以直接调用 |
| 类型安全 | 较低 | 较高 |
| 推荐使用 | 尽量避免滥用 | 接收未知数据时优先使用 |

---

### 二、`any` 的使用

`any` 相当于告诉 TypeScript：不需要检查这个变量的类型。

\`\`\`ts
let value: any = "Hello";

// 可以直接访问属性
console.log(value.length);

// 可以调用方法
value.toUpperCase();

// 可以随意修改类型
value = 123;

value.toFixed(2);
\`\`\`

即使类型不匹配，TypeScript 通常也不会报错。

\`\`\`ts
let value: any = "Hello";

value.toFixed(2); // 编译时不会报错
\`\`\`

但是运行时会报错，因为字符串没有 `toFixed()` 方法。

**缺点：** `any` 会让 TypeScript 失去类型检查的保护。

---

### 三、`unknown` 的使用

`unknown` 表示一个暂时无法确定具体类型的值。

\`\`\`ts
let value: unknown = "Hello";

// ❌ 报错：不能直接访问未知类型的属性
// console.log(value.length);

// ❌ 报错：不能直接调用未知类型的方法
// value.toUpperCase();
\`\`\`

必须先确认类型，才能进行操作。

#### 1. 使用 `typeof` 进行类型缩小

\`\`\`ts
let value: unknown = "Hello";

if (typeof value === "string") {
  console.log(value.length);        // 5
  console.log(value.toUpperCase()); // HELLO
}
\`\`\`

当 `typeof value === "string"` 成立时，TypeScript 会将 `value` 缩小为 `string` 类型。

#### 2. 使用类型断言

\`\`\`ts
let value: unknown = "Hello";

const str = value as string;

console.log(str.toUpperCase()); // HELLO
\`\`\`

这里通过 `as string` 告诉编译器将 `value` 视为字符串。

注意：类型断言不会检查真实类型，也不会转换实际值。

---

### 四、`any` 和 `unknown` 的赋值区别

#### 1. `any` 可以赋值给其他类型

\`\`\`ts
let a: any = "Hello";

let b: string = a;
let c: number = a;
let d: boolean = a;
\`\`\`

即使实际值是字符串，也可以赋值给 `number` 类型的变量，不会产生类型检查错误。

#### 2. `unknown` 不能直接赋值给其他具体类型

\`\`\`ts
let a: unknown = "Hello";

// ❌ 报错
// let b: string = a;

// ✅ 先进行类型判断
if (typeof a === "string") {
  let b: string = a;
}
\`\`\`

因为 `unknown` 可能是字符串、数字、对象或其他类型，必须先确认。

---

### 五、实际开发中如何选择？

#### 1. `unknown`：接收不确定类型的数据

例如从外部接口、JSON 解析或其他不可信来源获取的数据。

\`\`\`ts
let data: unknown = JSON.parse('{"name":"张三"}');

if (typeof data === "object" && data !== null) {
  console.log(data);
}
\`\`\`

#### 2. `any`：暂时无法处理类型的场景

例如迁移旧 JavaScript 项目时，暂时需要绕过类型检查。

\`\`\`ts
let data: any = "Hello";

data.someMethod(); // 编译时不会报错
\`\`\`

---

### 六、总结

- **`any`：我不想让 TypeScript 检查这个值。**
- **`unknown`：我还不知道这个值是什么类型，确认之后才能使用。**

简单来说，`unknown` 可以看作是更安全的“任意类型”，适合处理未知数据。

## 3.类型断言和可选属性  
### 1.as
as 是告诉编译器怎样看待值,as 不会转换真实数据
```
const input: unknown = "12";
const count = input as number;

console.log(typeof count); // string
console.log(count + 1);    // 121
```
### 2.类型断言（Type Assertion）
它只影响 TypeScript 编译器的判断，不会在运行时把字符串转换成数字。`typeof`是 JavaScript 运行时操作。需要把字符串转数字时使用 Number()，不要写 as number。类型断言和可选属性都需要判断后再使用
```js
  let input: unknown = "18";
// ❌ 类型断言：不会真正转换类型
let age = input as number;
console.log(age + 1);        // "181"
console.log(typeof age);     // "string"

// ✅ 使用 Number()：真正转换为数字
let realAge = Number(input);

console.log(realAge + 1);    // 19
console.log(typeof realAge); // "number"
```

## 4.数组与元组  
### 元组是什么
元组（Tuple）是 TypeScript 中一种特殊的数组类型，用来规定数组中每个位置的元素类型和数量。
```ts
// 普通数组
let arr: (string | number)[] = ["小明", 18];

arr.push(20); // 可以
arr.push("北京"); // 可以

// 元组
let user: [string, number] = ["小明", 18];

// user[0] 必须是 string
// user[1] 必须是 number
```
### 元组解决了什么问题
#### 1. 解决数组中不同位置类型不明确的问题
普通数组使用联合类型时，无法明确规定每个位置的类型。
```
let user: (string | number)[] = ["小明", 18];
user = [18, "小明"]; // 也可以通过类型检查
```
使用元组后：
```
let user: [string, number] = ["小明", 18];

// ❌ 报错：位置类型不匹配
// user = [18, "小明"];
```
**元组可以明确规定每个位置的类型和顺序。**

## 5.对象类型和类型别名  
对象值和对象类型都有花括号  
```js
  const employee: {
  employeeNumber: string;
  name: string;
  remainingLeaveDays: number;
} = {
  employeeNumber: "EMP-001",
  name: "田中",
  remainingLeaveDays: 12,
};

console.log(employee.name);               // 田中
console.log(employee.remainingLeaveDays); // 12
```

定义并使用类型别名  
```js
  type Employee = {
  readonly employeeNumber: string;//默认是浅层限制
  readonly profile?: {
    displayName: string;
  };
  name: string;
  nickname?: string;//可以赋值也可以不赋值，不赋值的情况下就不存在
};

const employeeA: Employee = {
  employeeNumber: "EMP-001",
  name: "田中",
  profile: {
    displayName: "田中",
  },
};

const employeeB: Employee = {
  employeeNumber: "EMP-002",
  name: "佐藤",
  nickname: "さとうさん",
};

console.log(employeeA.nickname); // undefined
if (employeeA.profile) {
  employeeA.profile.displayName = "tanaka";
}
if (employeeA.profile) {
  console.log(employeeA.profile.displayName);
}
console.log(employeeB.nickname); // さとうさん
```
